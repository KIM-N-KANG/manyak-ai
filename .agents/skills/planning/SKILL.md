# 계획 수립 (planning)

## 목적

비자명한 새 작업을 코드부터 짜지 않고, 먼저 조사·질문해 방향을 합의하고,
계획을 작업 리스트로 다듬어 승인받습니다. 핵심은 빨리 계획을 내는 게 아니라,
추측 기반 구현이 쌓이기 전에 방향을 맞추는 것입니다. 계획 단계에서는 아무것도
바꾸지 않고(파일·VCS·이슈 트래커 모두 읽기만) 어떤 작업·환경에도 쓰는 독립 스킬입니다.

## 핵심 원칙

- 승인 전에는 파일 생성·코드 변경을 하지 않습니다 — 플랜 모드로 강제합니다.
- 추측 금지 — 모호하면 먼저 조사하고, 그래도 불명확하면 질문합니다.
- 확인된 사실과 추정을 구분합니다 — 추정은 사실인 양 계획에 넣지 말고, 질문으로
  확인하거나 '가정'으로 드러냅니다. 확인 안 된 지점이 남으면 초안 전에 질문으로 해소합니다.
- 조사 깊이는 작업에 비례합니다 — 복잡·생소·교차 변경이면 깊게, 단순하면 가볍게.
  과·소 조사 둘 다 피합니다.
- 비자명 여부가 애매하면 trivial로 단정하지 말고 계획 쪽으로 기웁니다.
- 계획을 한 번에 끝내지 않습니다 — 제시 → 재고 → 리스트화로 다듬습니다.
- 항목 크기: 1 항목 = 1 리뷰 단위(커밋 1~수개).
  기준은 "이 항목만 보고 커밋/PR을 만들 수 있나?"입니다.
- 효용·전제가 검증 안 된 작업은 계획만 남기고 구현은 보류합니다.

## 작업 흐름

1. 플랜 모드 진입 — 승인 전까지 편집을 차단합니다.

2. 조사 — 깊이는 작업에 맞춰 스스로 정하고, "무엇을 확인할지"를 중심에 둡니다.
   - 기본(가벼운 작업): 바뀔 코드 주변과 관련 명세·접점을 직접 확인합니다.
   - 딥리서치(복잡·생소·교차 변경 시 격상): 여러 각도에서 확인하고 종합합니다.
     - 코드베이스 조사 — 바꿀 대상과 그 의존·호출 관계, 명명·구조 관습.
     - 관련 저장소 확인 — 접점·계약이 맞물리는 인접 저장소(프런트/백엔드 등).
     - 명세·설계 정본 확인 — 해당 작업의 설계·계약을 정한 문서.
     - 외부 문서 확인 — 쓰려는 라이브러리·표준·API의 실제 동작.
   - 발견사항을 종합해 계획 근거로 사용자에게 제시합니다(투명하게).
   - 격상 신호: 생소한 서브시스템 / 저장소 간 접점 변경 / 접근법이 여러 개 /
     외부 기술 미상 / 요청이 높은 수준이라 'how'가 안 잡힘.

3. 자문 질문 — 조사로도 안 풀린 모호함만 묻습니다(추측 금지).

4. 초안 리스트 제시 — 부모 목표(1~3줄)와 항목들을 내고, 왜 이런 순서·작업 구성을
   택했는지 간단한 근거를 함께 설명합니다. 각 항목의 포함·완료기준은 조사·합의에서
   끌어오고, 모르는 부분은 지어내지 말고 비워 둔 채 질문합니다. 사용자가 리스트
   자체가 아니라 계획의 이유를 이해하도록 합니다.

5. 반복 다듬기 — 피드백으로 항목 크기·순서·완료기준을 조정합니다.
   첫 안을 그대로 옮기지 않고 판단을 보탭니다.

6. 계획 승인 — 확정 리스트를 제시해 승인받습니다(플랜 모드의 승인 게이트).

7. 종료 — 승인되면 확정 리스트로 멈춥니다. 구현을 시작하지 않습니다(별도).

## 산출물 형식

- 부모 목표: 1~3줄 (무엇을·왜).
- 작업 리스트: 항목별 `id` / `title` / `desc`(목적·포함·완료기준) /
  (필요 시 순서·의존).

예시:

```
부모 목표: <무엇을·왜, 1~3줄>

작업 리스트:
- id 1 | title: … | desc: 목적=… / 포함=… / 완료기준=…
- id 2 | title: … | desc: 목적=… / 포함=… / 완료기준=… | 의존: 1
```

## 금지 사항

- 승인 전에 파일 생성·코드 수정·외부 시스템 쓰기를 하지 않습니다.
- 사전조사·질문 없이 추측으로 계획을 확정하지 않습니다.
- 확인 안 된 사실을 단정해 계획에 넣지 않습니다 — 모르면 질문하거나 '미확인/가정'으로 표시합니다.
- 계획을 한 번에 던지고 다듬기를 생략하지 않습니다.
- 항목을 단일 라인(너무 잘게)·기능 전체(너무 크게)로 쪼개지 않습니다.
- 승인 후 멋대로 구현을 시작하지 않습니다 — 이 스킬은 계획까지입니다.

## 완료 보고

- 확정된 부모 목표와 작업 리스트를 보고합니다.
- 딥리서치를 했으면 핵심 발견을 한 줄로 요약합니다.
- 계획에 깔린 가정(검증 안 된 전제)이 있으면 명시합니다.
- 보류·미결 항목(효용 미검증 등)이 있으면 명시합니다.
