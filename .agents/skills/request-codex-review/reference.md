# request-codex-review 참고

`SKILL.md`가 가리키는 절의 상세다. 필요한 절만 펼쳐 본다.

## §1 비자명한 규칙 (스크립트가 왜 이렇게 생겼나)

아래는 전부 **스크립트가 이미 처리한다.** 손으로 `gh` 명령을 짜지 말고 스크립트를 쓰라는 근거이자,
스크립트를 고칠 때 깨뜨리면 안 되는 것들이다.

- **Codex는 draft PR을 리뷰하지 않는다.** 그래서 `request-review.sh`가 호출 전에 draft면 ready로
  올린다. (메모리: `codex-review-needs-ready-pr`)
- **호출은 PR 본문이 아니라 코멘트 `@codex review`로만 트리거된다.**
- **리뷰는 즉시 오지 않는다**(보통 수 분~20분). 폴링으로 도착을 감지해야 한다.
- **봇 계정 이름이 두 형태로 온다.** `chatgpt-codex-connector[bot]`이 기본이지만 환경·이벤트에 따라
  접미사 없이 `chatgpt-codex-connector`로도 보고된다. 한 형태로만 매칭하면 응답이 왔는데도 카운트가
  0에 머물러 timeout이 난다. 그래서 **두 이름을 각각 정확히 비교**한다.
  `contains("codex-connector")` 같은 부분 일치는 쓰지 않는다 — 공개 레포라 누구나
  `evil-codex-connector-fan` 같은 계정으로 코멘트·리액션을 남길 수 있고, 그러면 남의 글을
  Codex 응답으로 오판한다.
- **지적이 없으면 정식 리뷰가 아예 안 생긴다.** Codex는 지적이 있을 때만 `pulls/{n}/reviews`를
  만들고, 없으면 "Didn't find any major issues" 같은 이슈 코멘트(`issues/{n}/comments`)나 호출
  코멘트의 thumbs-up 리액션으로만 답한다. 그래서 리뷰 수만 폴링하면 "지적 없음"을 놓쳐 timeout이
  난다. **세 신호(리뷰 수 증가 · 봇 이슈 코멘트 증가 · 봇 thumbs-up) 중 하나**로 감지한다.
  thumbs-up은 반드시 **봇 것만** 센다 — 사람이 먼저 누르면 오탐한다.
  (메모리: `codex-review-as-issue-comment`)
- **GitHub API는 기본 30개씩 페이지네이션된다.** 코멘트가 많은 PR에서는 새 응답이나 봇 리액션이
  2페이지 뒤로 밀려 1페이지만 세면 감지에 실패한다. 그래서 항상 `--paginate`(+`per_page=100`)다.
  `--slurp`는 `--jq`와 같이 못 쓴다(gh 에러).
- **`gh api | awk`로 파이프하면 gh 실패가 awk의 성공에 가려져 조용히 0이 된다.** 기준선이 거짓
  0이면 옛 코멘트를 이번 응답으로 오인해 조기 종료한다. 그래서 `codex_count`는 gh 출력을 먼저
  받아 실패 시 `return 1`로 전파하고, 그다음에 `awk`로 합산한다. 기준선 단계에서 실패하면
  중단하고, 폴링 중 실패하면 이전 값을 유지한다.
- **에이전트의 Bash 도구는 호출마다 셸 상태를 초기화할 수 있다.** 그래서 기준선·호출 코멘트
  id·head 커밋을 변수로 물려주지 못하고 상태 파일에 적는다(§5).

## §2 신호 해석 (`wait-review.sh` 종료코드)

| 코드 | 출력 | 뜻 | 다음 |
|---|---|---|---|
| 0 | `THUMB_UP` | 봇이 호출 코멘트에 thumbs-up. **추가 지적 없음(확정)** | 완료 보고 |
| 10 | `REVIEW_ARRIVED` | 정식 리뷰가 달렸다 = 지적이 있다 | `show-review.sh`로 본문 |
| 11 | `COMMENT_ARRIVED` | 이슈 코멘트가 왔다 | `show-review.sh`로 본문 |
| 3 | `NOT_YET` | 아직 안 왔다 | 같은 명령을 그대로 다시 실행 |
| 1 | `FAIL: …` | 상태 파일 없음·조회 실패 | §4 |

**0만이 통과의 확정 신호다.** 10·11은 승인으로 단정하지 않는다 — 이슈 코멘트에도 질문이나 새 지적이
섞인다. 본문을 읽기 전에는 "머지 가능"으로 보고하지 않는다.

## §3 메이저·마이너 판단

`show-review.sh` 출력을 놓고 나눈다.

- **메이저(반영 필요)** — 동작이 틀리거나, 데이터가 깨지거나, 보안·비밀 노출이 걸리거나,
  계약(요청·응답 스키마)이 어긋나는 지적.
- **마이너·제안(보류 가능)** — 취향·스타일, 이번 티켓 범위 밖 개선, 근거가 약한 추측.

규칙:

- **지적을 명령으로 재현한 뒤에만 받아들인다.** 재현 명령과 그 출력을 보고에 담는다.
  재현되지 않으면 반려하고 근거를 댄다 — 실제로 틀린 지적이 있었다(예: 존재하지 않는 브랜치 보호
  규칙, 이미 있는 GitHub Secrets를 "0개"라고 한 것).
- 메이저는 사용자 확인 없이 무시하지 않는다.
- 반영 여부가 애매하면 임의로 고치지 말고 사용자 판단을 받는다.
- 지적이 틀렸다고 판단하면 그 근거(명령·파일·줄)를 대고 반박한다. "확인했다"만으로 넘기지 않는다.
- 이슈 코멘트가 "no major issues"류이고 정식 리뷰·인라인 지적이 없으면 "메이저 없음"으로 보고한다.
- **고친 뒤에는 다시 리뷰를 받는다.** 수정이 새 결함을 만든 적이 있다 — 한 번은 고치려던 안전장치가
  오히려 전보다 더 많이 뚫렸고, 옛 버전과 나란히 돌려 보고서야 드러났다.

## §3-1 Codex와 별개로 직접도 훑는다

Codex에만 맡기지 않는다. 둘이 찾는 것이 다르다 — Codex는 셸·인용·경계값을 집요하게 파고, 직접 보는
쪽은 "이 변경의 의도가 무엇이었나"를 안다. 실제로 같은 변경에서 서로 다른 결함을 찾아냈다.

직접 훑을 때의 관점:

- **실패가 성공으로 보이는 자리** — 명령 실패를 검사하지 않는 곳, 빈 결과와 오류를 구분 못 하는 곳.
- **문서가 단언하는 것과 코드가 하는 것** — 주석·문서에 "이래서 안전하다"고 적혀 있으면 그게 사실인지 본다.
- **같은 사실이 두 곳에 적힌 자리** — 한쪽만 고쳐지면 조용히 어긋난다.

## §4 트러블슈팅

- **`FAIL: 상태 파일이 없습니다`** — `request-review.sh`를 안 돌렸거나, 임시 디렉터리가 청소됐다.
  `request-review.sh <PR>`를 다시 돌리면 된다(코멘트가 하나 더 달릴 뿐 해롭지 않다).
- **`FAIL: PR #N 을 찾을 수 없습니다`** — PR이 아직 없다. `create-pr`이 먼저다.
- **`FAIL: 기준선 조회 실패`** — 대개 `gh` 인증이다. `gh auth status`를 본다.
- **`NOT_YET`이 세 번 이상** — Codex가 호출을 못 받았을 수 있다. PR에 `@codex review` 코멘트가
  실제로 달렸는지, PR이 ready인지 확인하고 사용자에게 알린다. 무한정 기다리지 않는다.
- **Bash 도구가 중간에 끊긴다** — `wait-review.sh`는 기본 540초를 기다린다. 도구 timeout을
  600000(10분)으로 주지 않으면 기본 2분에서 잘린다.
- **응답이 왔는데 감지가 안 된다** — 봇 이름 필터나 페이지네이션을 의심한다(§1). 확인은
  `gh api --paginate "repos/<owner>/<repo>/issues/<PR>/comments?per_page=100" --jq '.[].user.login'`.

## §5 상태 파일

`${TMPDIR:-/tmp}/codex-review-<PR번호>.env` 하나에 이번 라운드 정보를 담는다.

| 키 | 쓰임 |
|---|---|
| `REPO` | `owner/name` |
| `PR` | PR 번호 |
| `PREV_REVIEWS`·`PREV_COMMENTS` | 호출 직전 봇 응답 수. 증가분으로 도착을 판정한다 |
| `CMTID` | 호출 코멘트 id. thumbs-up을 여기서 센다 |
| `HEAD_SHA` | 이번 라운드 head 커밋. `show-review.sh`가 옛 라운드를 걸러내는 기준 |

재리뷰 때 `request-review.sh`를 다시 돌리면 이 파일을 통째로 덮어쓴다 — push로 head가 바뀌었으니
`HEAD_SHA`도 새로 잡혀야 `show-review.sh`가 새 라운드만 보여준다.
