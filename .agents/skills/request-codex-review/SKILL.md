# Codex 리뷰 요청·반영 루프

`create-pr`로 만든 PR에 Codex 리뷰를 받고, 지적을 판단해 반영하고, 필요하면 재리뷰까지 받는
한 사이클을 끝낸다. 코멘트를 남기는 게 목적이 아니라 **Codex가 실제로 리뷰를 시작하게 만들고,
도착을 확인하고, 지적의 경중을 판단하는 것**이 목적이다.

## 같이 쓰는 파일

경로는 레포 루트 기준이다.

- `.agents/skills/request-codex-review/scripts/` — `request-review.sh` · `wait-review.sh` · `show-review.sh`.
  **읽지 말고 실행한다.** 셋 다 종료코드가 판정이다. `gh` 명령을 손으로 짜지 않는다 —
  봇 이름 두 형태, 페이지네이션, 실패 삼킴 같은 함정이 스크립트 안에 이미 들어 있다.
- `.agents/skills/request-codex-review/reference.md` — 왜 그렇게 짰는지(§1), 신호 해석(§2),
  메이저·마이너 판단(§3), 트러블슈팅(§4), 상태 파일(§5).

## 하드 룰

- **본문을 읽기 전에 "리뷰 통과"로 보고하지 않는다.** 확정 통과 신호는 봇 thumbs-up(종료코드 0)뿐이다.
- 폴링을 건너뛰고 결과를 추측하지 않는다.
- **지적은 명령으로 재현한 뒤에만 받아들인다.** 재현되지 않으면 반려하고 근거를 댄다.
  실제로 지적이 틀린 적도, 고친 것이 새 결함을 만든 적도 있다 → §3
- Codex에만 맡기지 않는다. 같은 변경을 **직접도 적대적으로 훑는다.** 둘이 찾는 것이 다르다 → §3
- 메이저 지적을 사용자 확인 없이 무시하지 않는다. 애매한 제안은 임의로 반영하지 않고 판단을 받는다.
- 사용자 지시 없이 머지하지 않는다(머지가 배포로 이어질 수 있다).

## 1단계 — 호출

- [ ] `bash .agents/skills/request-codex-review/scripts/request-review.sh <PR번호>`
      draft면 ready 전환까지 알아서 한다. 종료코드 1이면 멈춘다 — PR이 없으면 `create-pr`이 먼저다.

## 2단계 — 도착 대기

- [ ] `bash .agents/skills/request-codex-review/scripts/wait-review.sh <PR번호>`
      **백그라운드로 돌린다.** 12분을 기다리는데 Bash 도구는 앞에서 10분까지만 버틴다 → §2
- [ ] 종료코드로 갈린다 → 상세는 `reference.md` §2
      - `0` — 추가 지적 없음(확정). 4단계로
      - `10`·`11` — 리뷰나 코멘트가 왔다. 3단계로
      - `3` — 아직. 같은 명령을 그대로 다시 실행한다(상태는 이어진다).
        세 번 연속 3이면 기다리지 말고 사용자에게 알린다
      - `1` — 실패. `reference.md` §4

## 3단계 — 읽고 판단

- [ ] `bash .agents/skills/request-codex-review/scripts/show-review.sh <PR번호>`
      이번 라운드(현재 head 커밋) 것만 나온다.
      **종료코드 4면 결과를 믿지 않는다** — 요청 뒤 커밋이 더 올라가 옛 커밋을 보고 있다. 1단계부터 다시 → §4
- [ ] 지적을 **메이저(반영 필요)** 와 **마이너·제안(보류 가능)** 으로 나눈다 → `reference.md` §3
- [ ] 메이저를 고쳤으면 커밋·push 후 **1단계부터 다시** — 같은 스크립트가 재리뷰도 처리한다

## 완료 보고

ready 전환 여부와 PR URL / 응답 유형(정식 리뷰·이슈 코멘트·thumbs-up)과 메이저·마이너 요약 /
반영한 것과 보류한 것 / 재리뷰 결과와 머지 가능 판단의 근거 / 확인 못 한 부분은 그대로.
