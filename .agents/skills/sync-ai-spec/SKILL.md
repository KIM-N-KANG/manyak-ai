# AI 서버 스펙 동기화 (sync-ai-spec)

`knk-harness/docs/product-specs/5-ai-server.md`는 AI 서버의 SSOT 스펙이다. 구현이 바뀌면 이 문서도
따라 바뀌어야 하는데, 사람 기억에 맡기면 조용히 어긋난다(드리프트). 이 스킬은 그 간극을 git으로 감지하고,
문서의 서술 철학(3층 서술)에 맞게 갱신한다.

## 같이 쓰는 파일

경로는 레포 루트 기준이다.

- `.agents/skills/sync-ai-spec/scripts/detect-drift.sh` — 드리프트 감지. **읽지 말고 실행한다.**
  종료코드가 판정이고, 감시 경로와 기준 SHA를 스스로 읽는다(손으로 옮겨 적지 않는다).
- `.agents/skills/sync-ai-spec/reference.md` — 층위 판단(§1), D 카탈로그 규칙(§2), 매핑·제안(§3),
  종료코드 대응(§4), 커밋·PR(§5), 금지 사항(§6), 완료 보고 형식(§7).

## 하드 룰

- **수정 대상은 `../knk-harness/docs/product-specs/5-ai-server.md` 하나뿐이다.** 하네스의 다른 문서는
  각자 소유자가 있다 — 불일치를 발견해도 고치지 말고 보고만 한다.
- **층위 판단이 먼저다.** 구현 변경이 곧 Implementation 수정은 아니다. 결정이 뒤집힌 변경을 값 표
  수정으로 처리하면 문서의 근거 서술이 거짓이 된다 → §1
- **확인 후 반영한다.** 갱신안(어느 층위·어느 결정·어느 섹션)을 먼저 보여주고 승인받은 뒤 고친다.
- **변경과 무관한 섹션은 재작성하지 않는다.** diff가 가리키는 좌표(결정 ID × 섹션)만 수정한다.
- **모호하면 질문한다.** 근거가 부족한데 Implementation으로 단정하지 않는다.
- 나머지 금지 사항 → §6

## 1단계 — 감지

- [ ] `bash .agents/skills/sync-ai-spec/scripts/detect-drift.sh`
- [ ] 종료코드로 갈린다 → 상세는 `reference.md` §4
      - `0` — 변경 없음. "스펙은 최신입니다"로 보고하고 끝낸다
      - `10` — 감시 경로 안에 변경 있음. 커밋(또는 머지 PR) 단위로 묶어 2단계로
      - `11` — 감시 경로 **밖** 변경만 있음. 끝내지 말고 그 커밋 메시지를 읽어,
        설계 변경을 시사하면 2단계로, 아니면 "스펙 최신"으로 보고한다
      - `1`·`3`·`4`·`5` — 스펙 파일 없음 / 앵커 SHA 없음 / 기준 SHA가 로컬에 없음 /
        fetch 실패. §4대로 대응한다. **실패를 "최신"으로 보고하지 않는다**

## 2단계 — 층위 판단 (변경 단위마다)

- [ ] 커밋 메시지·PR 본문·`spec/` 동반 변경을 함께 읽고, Context → 결정 → 구현 순으로 묻는다 → §1
- [ ] 결정이 걸리면 D 카탈로그 규칙을 적용한다 → §2

## 3단계 — 매핑과 제안

- [ ] 영향받는 결정 ID × 섹션의 교차점만 대상으로 잡는다. 간극 표(A*) 영향도 포함 → §3
- [ ] 갱신안을 보여주고 **승인받는다**

## 4단계 — 갱신

- [ ] 승인받은 좌표만 수정한다. 3층 서술 순서·§5-2 단일 서술·기존 문체·LF 유지 → §3
- [ ] 메타 표 갱신 — 기준 코드 SHA(스크립트가 출력한 12자리), 작성일, 버전(+0.1)

## 5단계 — 커밋·PR

- [ ] knk-harness에서 pull 후 분기 → 공용 스킬로 커밋·Draft PR → §5
