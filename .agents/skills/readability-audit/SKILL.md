# 가독성 감사 (readability-audit)

## 목적

기술 문서·스펙을 "처음 읽는 사람" 기준으로 감사해, 읽기를 막는 지점을 리스트로
보고한다. 핵심은 고치는 것이 아니라 **찾아서 보여주는 것**이다 — 수정은 사용자가
항목을 골라 승인한 뒤의 별도 단계다. 감사와 수정을 한 번에 하면, 사용자가 원치
않는 변경이 문서에 섞여 들어간다.

## 하드 룰

- **기본 모드는 읽기 전용이다.** 감사 요청만으로는 문서를 한 글자도 수정하지 않는다.
- **결과는 대화에 바로 출력한다.** 별도 파일로 저장하지 않는다(사용자가 저장을
  명시로 요청한 경우만 예외).
- **git 작업(커밋·브랜치)은 하지 않는다.** 반영 단계에서도 수정까지만 하고,
  커밋은 변경 요지 보고 → 사용자 확인 → `create-commit` 순서를 따른다.

## 검출 기준 (무엇을 잡나)

1. **낯선 용어** — 더 흔히 쓰는 말이 분명히 있는데 쓴 용어.
   판단 질문: "이 분야 신입이 이 단어를 검색 없이 이해하나?", "팀이 평소 쓰는 말인가?"
   - 예(실제 지적 이력): 보폭, 퇴거 정책, 꼬리 위험, 절삭, 범프, 감쇠, 동결,
     nested, prefix 같은 번역투·전문투 — 풀어 쓰거나 흔한 말로 바꾼다.
   - 도메인 공식 용어는 예외다: `0-glossary.md`에 정의된 용어는 낯설어도 정본이다.
     glossary 용어를 "낯설다"고 지적하지 않는다.
2. **어색한 문장** — 번역투, 주어-술어가 꼬인 문장, 한 문장에 절이 3개 이상,
   의미가 두 갈래로 읽히는 문장.
3. **문장 안에 박힌 참조** — "D7에 따라 ~", "§5-3처럼 ~"이 문장 중간에 있으면
   읽는 사람이 그게 뭔지 보러 갔다 와야 한다. 문장은 내용을 풀어서 쓰고,
   참조는 문장 밖(끝 태그·괄호)으로 분리하도록 제안한다.
4. **설명 없는 축약·기호** — 처음 등장하는 약어·필드명·내부 코드네임이
   풀이 없이 쓰인 곳.

## 작업 흐름

1. **대상 확정** — 감사할 문서(들)와 범위(전체/특정 절)를 확인한다.
   지정이 없으면 추측하지 말고 묻는다.
2. **통독** — 대상을 처음부터 끝까지 읽는다. 발췌만 읽고 지적하지 않는다.
3. **검출 리스트 출력** — 대화에 아래 형식으로 출력한다. 표가 아니라 텍스트
   리스트로 쓴다(항목 안에 설명이 길어지면 표는 읽기 어렵다).

   ```
   1. [위치: §절 이름 또는 인용 어구]
      - 원문: "…"
      - 문제: 낯선 용어 | 어색한 문장 | 인라인 참조 | 설명 없는 축약
      - 제안: "…" (바꾸면 이렇게 된다)
   ```

   확실한 결함과 취향 차이를 구분한다 — 취향에 가까운 항목은 "취향 수준"이라고
   표시해 사용자가 걸러낼 수 있게 한다.
4. **선택 대기** — 어떤 항목을 반영할지 사용자 선택을 기다린다. 전 항목 일괄
   반영을 먼저 제안하지 않는다.
5. **(승인 후) 반영** — 승인된 항목만, 문장 단위 최소 수정으로 반영한다.
   승인 안 된 항목을 "내친김에" 고치지 않는다. 수정 대상이 `prompt/`·`spec/`
   파일이면 frontmatter `version`(+1)·`updated`(오늘)를 올리고 LF를 유지한다.
   knk-harness 문서라면 해당 레포 규칙(존댓말 문체 등)을 따른다.

## 쉬운 설명 모드 (부속)

감사 중이든 아니든, 사용자가 항목 "설명"을 요청하면 3단 형식으로 출력한다
(반복 요청으로 굳어진 팀 형식):

```
- 원설명: (문서의 원문 그대로)
- 풀어서: (전공 지식 없이 읽히는 설명)
- 초등학생 버전: (비유·일상어만으로)
```

## 금지 사항

- 감사 요청만 받고 문서를 수정하지 않는다.
- 결과를 파일로 저장하지 않는다(명시 요청 예외).
- glossary 정의 용어를 낯선 용어로 지적하지 않는다.
- 발췌만 읽고 문서 전체를 판정하지 않는다.
- 승인되지 않은 항목을 반영하지 않는다.
- 반영하면서 지적 목록에 없던 문장을 함께 다듬지 않는다.

## 완료 보고

- (감사) 검출 항목 수를 유형별로 요약하고, 리스트 전문을 대화에 출력했음을 확인한다.
- (반영) 반영한 항목 번호와 수정 파일, 보류한 항목을 구분해 보고한다.
- frontmatter 버전을 올린 파일이 있으면 명시한다.
