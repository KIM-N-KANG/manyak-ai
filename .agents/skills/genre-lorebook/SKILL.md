# 장르 로어북 크롤링 (genre-lorebook)

## 목적

장르 이름 하나로 나무위키 크롤 → 청크 분할 → worldview/character/cliche/story
4축 정제 → 로어북 병합까지, 사람 개입 없이 끝까지 수행한다. 무협(wuxia)에 대해
과거 손으로 만들었던 작업(`references/wuxia/`, `references/lore-book/wuxia.md`)을
재사용 가능한 절차로 표준화한 것이다.

## 배경(전제)

- 이 스킬은 `scripts/`(git-ignore, 로컬 전용)의 기존 도구를 그대로 재사용한다 —
  `namu_crawl.py`(크롤, curl 기반, Playwright 불필요), `split_raw.py`(청크 분할).
  새 크롤러를 만들지 않는다.
- 산출물(4축 정제본·로어북)은 `references/`(git-ignore) 아래 저장한다. 이 스킬이
  만드는 파일은 전부 로컬 전용이며, `SKILL.md` 자체만 git 추적 대상이다.
- 형식 기준(골든 샘플)은 기존 `references/{wuxia,academy,apocalypse}/`와
  `references/lore-book/{wuxia,academy,apocalypse}.md`다.
- **효용은 아직 실측 전이다.** 이 4축 KB·로어북이 실제 스토리/채팅 LLM 출력 품질을
  유의미하게 개선하는지는 별도 후속 작업(실측)의 몫이며, 이 스킬의 완료 기준에는
  포함되지 않는다.

## 핵심 원칙

- **완전자동, 사람 체크포인트 없음.** 유일한 예외는 "나무위키에 대상 문서 자체가
  없다"처럼 진행 자체가 불가능한 경우뿐이다(작업 승인 체크포인트가 아니라 데이터
  존재 확인).
- **결정적 단계는 기존 스크립트를 그대로 호출한다.** 크롤·청크 분할에 새 코드를
  만들지 않는다.
- **자연어 판단이 필요한 단계는 서브에이전트(Agent 도구)로 처리한다.** 관련 문서
  판단(가벼운 필터링은 예외 — 아래 참고), 4축 추출, 로어북 병합이 해당한다.
- **한글 표시용과 영문 슬러그 경로용을 분리한다.** 경로·파일명에 절대 한글을 쓰지
  않는다. 문서 제목·본문은 한글 장르명을 쓴다.
- **나무위키 예의를 지킨다.** `namu_crawl.py`의 기본 `--delay`(1.0초)를 임의로
  낮추지 않는다.
- **실패 관용.** 개별 문서 크롤 실패는 전체를 막지 않는다 — `namu_crawl.py`가 이미
  실패를 로깅하고 계속 진행한다.

## 입력

- 필수: 장르명(한글, 사용자가 부른 그대로. 예: "로맨스 판타지")
- 선택: 나무위키 시드 문서명(장르명과 다르면 사용자가 명시. 기본은 장르명과 동일하다고 가정)

## 작업 흐름

### 0. 사전 확인

- `test -f scripts/namu_crawl.py scripts/split_raw.py`로 두 스크립트가 있는지 확인한다.
- 같은 슬러그의 기존 산출물(`references/<slug>/`, `references/lore-book/<slug>.md`)이
  이미 있으면, 덮어쓰기 전 사용자에게 알린다(재실행·갱신 의도 확인 — 데이터 유실
  방지 목적이며 작업 체크포인트는 아니다).

### 1. 슬러그 결정

한글 장르명을 영문 kebab-case 슬러그로 직접 변환한다(서브에이전트 불필요).
예: "로맨스 판타지" → `romance-fantasy`, "정통 판타지" → `traditional-fantasy`,
"헌터물" → `hunter`. 이후 모든 경로·파일명은 슬러그를, 문서 제목·본문은 한글
장르명을 쓴다.

### 2. 시드 확장 (재귀 harvest, 완전자동)

1. 시드 문서(기본: 장르명 자체)로 시작한다.
2. `python3 scripts/namu_crawl.py --harvest "<시드문서>"`로 1-hop 링크(문서 제목
   목록)를 수집한다.
   - 결과가 비어 있으면(문서 없음) 사용자에게 정확한 나무위키 문서명을 확인한다
     (유일한 예외적 확인 지점).
3. 수집된 제목을 직접 훑어 장르와 관련 있는 문서만 화이트리스트에 추가한다
   (제목만 보는 가벼운 필터링이라 서브에이전트 없이 직접 판단한다).
4. 화이트리스트에 새로 들어온 문서마다 다시 `--harvest`로 1-hop 확장한다
   (재귀 깊이 상한 2 — 시드가 깊이 0, 1차 확장이 깊이 1, 이번이 깊이 2. 3-hop
   이상 확장하지 않는다). 확장 문서마다 개별 `--harvest`(curl 1회 + delay)라
   시간이 든다 — 깊이 2에서 수십 회 호출될 수 있으니 harvest 호출 수를 세어
   최종 보고에 남긴다.
5. 총 문서 수 상한(`max_pages`, 기본 150)에 도달하면 확장을 멈춘다. 도달 시
   "상한 도달, N개 수집 후 중단"을 최종 보고에 남긴다(은폐 금지).
6. 확정된 시드 목록을 `scripts/raw/<slug>-seeds.txt`(한 줄에 문서 제목 1개)로
   저장한다. **시드 문서 자신(장르명 문서)을 목록 맨 앞에 반드시 포함한다** —
   `--harvest`는 시드 내부 링크만 반환하고 시드 자신은 넣지 않으므로, 빠뜨리면
   장르의 핵심 문서 본문이 크롤에서 누락된다.

### 3. 크롤 (결정적, 기존 스크립트)

```bash
python3 scripts/namu_crawl.py \
  --seeds scripts/raw/<slug>-seeds.txt \
  --out scripts/raw/<slug>-1.md \
  --genre-name "<한글 장르명>" \
  --seed-desc "\"<시드문서>\" 시드에서 관련 문서를 재귀 탐색(깊이 2, 상한 <max_pages>)해 본문 수집" \
  --delay 1.0 \
  2> scripts/raw/<slug>-crawl.log
```

stderr는 `scripts/raw/<slug>-crawl.log`로 저장한다. 그 로그에서 OK/FAIL/EMPTY를
읽어 최종 보고에 요약한다(성공 수·실패 목록). 로그 파일은 정리 단계(8)에서 삭제한다.

### 4. 청크 분할 (결정적, 기존 스크립트)

```bash
python3 scripts/split_raw.py --src scripts/raw/<slug>-1.md --outdir scripts/_chunks --prefix <slug>
```

출력은 `scripts/_chunks/<slug>-chunkNN.md` 여러 개다.

### 5. 4축 정제 — MAP (서브에이전트, 청크마다 1개, 병렬)

청크마다 Agent 도구를 하나씩, 한 메시지에 모아 병렬로 호출한다(서로 독립된
작업). 각 서브에이전트에게 그 청크 파일 하나만 Read하게 하고, 아래 4축 정의를
그대로 전달해 4개 섹션(`### 세계관` / `### 인물` / `### 클리셰` /
`### 스토리·서사`)으로 나눠 메모를 반환하게 한다.

- **세계관**: 세계 구조·세력·제도·기술체계 (인물·줄거리 제외)
- **인물**: 인물 유형·위계·호칭·관계 (세계관 설정·기술 상세 제외)
- **클리셰**: 반복 설정·전개 (항목마다 개념→공식→변형→부작용 4단)
- **스토리·서사**: 장르 계보·세대·하위장르·서사 구조·주제 (세력도·개별 캐릭터 제외)

스타일 지시: 불릿 위주, 고유명사 보존, 볼드 용어 정의, 항목당 20~150자.
각 서브에이전트는 정제 메모만 반환한다(원문 재수록 금지) — 이 반환값이 6단계
입력으로 메인 컨텍스트를 거치기 때문이다.

### 6. 4축 정제 — REDUCE (서브에이전트, 축마다 1개, 총 4개)

축마다 Agent 도구를 1개 호출해, 그 축에 해당하는 모든 청크 메모(5단계 결과에서
해당 섹션만 추려 전달)를 입력으로 주고 중복 제거·정리해 최종 문서를 쓰게 한다.

청크가 많으면(대략 30개 초과) MAP 반환 총량이 커져 한 REDUCE 호출에 다 싣기
어렵다 — 그럴 땐 축마다 2단계로 나눈다(청크 그룹별 1차 병합 → 그룹 결과 2차
병합). 그래야 한 번에 실리는 메모량이 컨텍스트를 넘지 않는다.

| 파일 | 헤더 |
|---|---|
| `references/<slug>/<slug>-worldview.md` | `# <한글 장르명> 세계관` |
| `references/<slug>/<slug>-character.md` | `# <한글 장르명> 인물` |
| `references/<slug>/<slug>-cliche.md` (ASCII, cliché 아님) | `# <한글 장르명> 클리셰` |
| `references/<slug>/<slug>-story.md` | `# <한글 장르명> 스토리·서사` |

각 파일 형식: 제목 → 목적 1~3문장 → `> 출처: 나무위키 <한글 장르명> 데이터셋 정제
(분류·노이즈 제거본)` → `## 소제목` 섹션들.

### 7. 로어북 병합 (서브에이전트 1개)

4축 문서 4개와 **형식 견본으로 기존 로어북 1개(`references/lore-book/wuxia.md`)를
함께 Read**하게 하고, 그 견본과 같은 구조로 재구성하게 한다. 견본을 반드시 읽혀야
하는 이유: 로어북의 항목 형식은 4축 문서에 없는 고유 형식이라, 4축만 보고는
재현할 수 없다.

- 최종 섹션 순서: `## 세계관` → `## 인물` → `## 서사·플롯` → `## 클리셰`.
- 각 항목 형식(견본과 동일):
  ```
  ### 항목명
  - **뜻**: …
  - **웹소설에서의 쓰임**: …
  - **자주 엮이는 것**: …
  ```

저장 경로: `references/lore-book/<slug>.md`, 제목: `# <한글 장르명> 웹소설 로어북`.

### 8. 중간 파일 정리

**최종 산출물이 모두 생성됐는지 먼저 확인한다** — `references/<slug>/`의 4축 4개와
`references/lore-book/<slug>.md`가 전부 존재해야 한다. 하나라도 없으면 삭제하지
말고 보고한다(중간 파일이 유일한 복구 수단이다).

확인되면 아래 중간 파일을 삭제한다(전부 로컬 전용):
- 청크: `scripts/_chunks/<slug>-*`
- 시드: `scripts/raw/<slug>-seeds.txt`
- 크롤 로그: `scripts/raw/<slug>-crawl.log`

크롤 원문 `scripts/raw/<slug>-1.md`는 **남긴다** — 재실행 시 재크롤(시간·나무위키
부하) 없이 청크 분할부터 재개할 수 있다.

### 9. 완료 보고

수집 문서 수(성공/실패), 상한 도달 여부, 청크 수, harvest 호출 수, 서브에이전트
호출 수, 절삭된 초대형 문서 수(`split_raw.py`가 `…(본문 일부 생략: 캡)` 마커를
남긴 섹션 수), 산출물 경로 5개(4축 4개 + 로어북 1개)를 보고한다. 실패 문서
목록이 있으면 숨기지 않고 함께 보고한다. 정리 단계(8)에서 삭제한 중간 파일과
남긴 크롤 원문(`scripts/raw/<slug>-1.md`)을 함께 밝힌다.

## 오류 처리

| 상황 | 대응 |
|---|---|
| 시드 문서 harvest 결과 0건 | 사용자에게 정확한 나무위키 문서명 확인(유일한 예외적 확인 지점) |
| 크롤 성공률이 낮음(예: 50% 미만) | 진행은 계속하되 최종 보고에 낮은 성공률과 원인 추정(Cloudflare 차단 등)을 명시 |
| `max_pages` 상한 도달 | 중단하고 "상한 도달, N개로 진행"을 보고에 명시(은폐 금지) |
| 청크가 1개뿐(소규모 장르) | 그대로 진행 — MAP 호출도 1회로 줄 뿐 절차는 동일 |
| 4축 총량이 커서 로어북 병합 1개 서브에이전트 컨텍스트를 넘음 | 축 2개씩 나눠 2회로 부분 병합 후 이어 붙인다(대개 `max_pages` 150이면 발생하지 않음) |
| 기존 산출물 존재(재실행) | 덮어쓰기 전 사용자에게 알림 |

## 금지 사항

- 한글로 경로·파일명을 만들지 않는다(슬러그는 항상 영문).
- `namu_crawl.py`의 `--delay`를 임의로 낮추지 않는다.
- raw·청크 원문을 메인 컨텍스트에서 직접 Read해 4축 정제·로어북 병합을 처리하지
  않는다 — 반드시 서브에이전트를 거친다(컨텍스트 한계, MAP-REDUCE 원칙).
- `max_pages`·재귀 깊이 상한을 넘겨 무한 확장하지 않는다.
- `references/`·`scripts/` 산출물을 git add하지 않는다(로컬 전용 — 이 스킬이
  git 추적 대상으로 만드는 파일은 `SKILL.md` 자체뿐이다).

## 완료 보고 형식

```
✓ <한글 장르명> 로어북 생성 완료 (슬러그: <slug>)

  시드 문서 수:      N개 (성공 a / 실패 b)
  harvest 호출:      H회
  청크 수:           M개
  절삭된 문서:       C개 (60KB 캡 초과 섹션)
  서브에이전트 호출: 청크 M + REDUCE 4 + 로어북 병합 1 = 총 (M+5)회
  산출물:
    references/<slug>/<slug>-worldview.md
    references/<slug>/<slug>-character.md
    references/<slug>/<slug>-cliche.md
    references/<slug>/<slug>-story.md
    references/lore-book/<slug>.md
  실패 문서:         {목록 또는 없음}
  상한 도달:         {예(N개에서 중단) | 아니오}
  정리:              청크·시드·크롤로그 삭제, 크롤 원문(<slug>-1.md) 유지
```
