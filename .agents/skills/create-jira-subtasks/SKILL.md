# Jira 서브태스크 생성·관리 (create-jira-subtasks)

확정된 작업 리스트(보통 `planning` 산출물)를 Jira에 반영하고, 작업 동안 부모 티켓과
서브태스크를 관리한다. **생성 후 정본은 Jira다** — 로컬에 작업 리스트 파일을 두지 않는다.

## 같이 쓰는 파일

- `.agents/skills/create-jira-subtasks/reference.md` — 절차 상세·판단 기준·금지 사항.
  아래에서 가리키는 절(§)만 펼쳐 본다.

## 하드 룰

- **본인 소유 티켓만 쓴다.** 쓰기 전에 `reporter`/`assignee`가 실행 계정인지 확인하고,
  아니면 건너뛰고 보고한다 → §1
- **전환 ID를 추측하지 않는다.** 매번 그 티켓의 현재 전환을 조회해 목표 상태 이름으로
  매칭한다. 갈 수 있는 전환이 없으면 강행하지 않고 보고한다 → §3
- **상태를 바꾸기 전에 대상과 `현재→목표`를 보여주고 확인받는다.** 일괄 전환은 표로 → §5
- **결과 기록 없이 `완료`로 보내지 않는다** → §4
- 티켓을 삭제하지 않는다. 접는 것은 `폐기` 전환으로만 → §2-3
- 동기화는 `planning → Jira` 한 방향이다. Jira를 읽어 계획을 재구성하지 않는다.
- 나머지 금지 사항 → §6

## 시작 전 확인

- [ ] 부모 키 — 현재 브랜치에서 추출
- [ ] 실행 계정(`/myself`)의 accountId
- [ ] 부모의 현재 description과 기존 서브태스크 — Jira가 현재 상태의 정본이므로,
      "무조건 생성"이 아니라 차이만 반영한다

## 무엇을 하느냐에 따라

- **작업 리스트를 처음 올린다** → §2-1. 키를 아직 못 받은 항목만 만든다(중복 방지).
  생성 시점에 description은 채우지 않는다
- **작업 중 항목 하나를 추가한다** → §2-2
- **항목을 접는다** → §2-3
- **"KNK-000을 〈상태〉로"** → §3-1. "부모 M 완료"는 일괄 전환이다
- **PR을 올렸다** → §3-2 (부모·서브태스크를 `PR 리뷰 및 검증`으로)
- **완료 처리** → §4. description에 결과를 먼저 쓰고 전환한다

## 커밋 키 핸드오프

커밋은 **작업 중인 서브태스크 키**, 브랜치·PR 제목은 **부모 키**다.
만든 키를 또렷이 들고 있다가 커밋 단계에 넘겨, 어느 키로 커밋할지 헷갈리지 않게 한다.
