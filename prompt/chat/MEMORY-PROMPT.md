# MEMORY-PROMPT

## 1. 상태 스키마 (세션 저장소의 JSON)

MVP 단계에서는 스탯(호감도·관계 수치 등) 없이 "대화 맥락"만 기억한다. 상태는 요약 한 칸으로 시작한다.

```json
{ "summary": "지금까지의 대화 맥락 요약 텍스트" }
```

> 향후 스탯이 도입되면 필드를 추가한다. 현 단계 상태는 `summary` 하나뿐이다.

## 2. Depth 주입 렌더 양식

조립기는 위 상태 JSON을 아래 양식으로 렌더해, 대화 내역 끝 가까이(끝에서 1~2번째)에 매 턴 삽입한다.

```text
[현재 상태]
{{summary}}
```

## 3. LLM 읽기 규칙

- `[현재 상태]` 블록은 **지금까지 이야기에서 확정된 사실과 진행 상황**이다. 이를 현재 시점의 진실로 받아들이고 응답을 전개한다.
- 이 블록의 내용이 앞쪽 시스템 설정(STORY의 가능성, CHARACTER의 초기 태도, USER의 시작 프로필)과 다를 경우, **진행 결과인 `[현재 상태]`가 우선**한다. (예: 초기 태도가 '경계'였어도 현재 상태가 '신뢰'면 신뢰로 연기한다.)
- 단, `[현재 상태]`가 SAFETY·CORE의 규칙을 덮어쓸 수는 없다. 인물의 본성을 붕괴(OOC)시키는 방향으로 해석하지 않는다.

## 4. 기록 규칙 (요약/추출 시)

- `summary`에는 **확정된 사실·진행 상황(Actuality)**과 누적된 변화(State)만 압축해 적는다.
- 아직 일어나지 않은 가능성(STORY 소관), 인물의 고정 성격(CHARACTER 소관), 시작 시점 프로필(USER 소관)은 적지 않는다.
- 갱신 시점: **직전 턴이 확정된 때(= 다음 사용자 입력이 도착한 때)** 요약/추출 LLM이 최근 대화 내역을 읽어 `summary`를 갱신한다. 재생성으로 폐기된 응답은 다음 입력 전이라 요약에 반영되지 않는다(재생성 기억 오염 차단).
- `summary`는 무한히 늘리지 않고, 최근 전개와 확정 사실 위주로 압축 유지한다.
