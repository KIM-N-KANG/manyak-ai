# LAYER-PLACEMENT.md

> 본 문서는 **[PROMPT-LAYER.md]의 레이어 정의(누가 무엇을 담당하는가)**와 **[CONTEXT-ARCHITECTURE.md]의 조립 원리(프롬프트가 어떻게 조립·주입되는가)**를 연결하는 **배치 명세서**다. 각 레이어가 실제 프롬프트 조립에서 **어디에·언제·얼마나 자주** 배치되는지를 확정하여, 이후 프롬프트 템플릿 작성의 기준선을 제공한다.

---

## 0. 이 문서가 메우는 공백

[PROMPT-LAYER.md]는 각 레이어가 **무엇(What)**을 담당하는지를 정의하고, [CONTEXT-ARCHITECTURE.md]는 프롬프트가 **어떻게(How)** 조립·주입되는지의 원리를 설명한다. 그러나 "CHARACTER 레이어에 적은 내용을 실제 프롬프트의 **어느 위치**에 넣어야 하는가"라는 배치 질문에는 두 문서 모두 직접 답하지 않는다.

이 문서는 그 공백을 메운다. 레이어(누가)와 조립 원리(어떻게 돌아가는가)를 묶어, 각 레이어가 **지금 실제로 어디에 서야 하는지**를 확정한다.

본 배치 규칙의 콘텐츠 소유권 및 메커니즘 귀속의 **정본(SSOT)은 [PROMPT-LAYER.md]**다. 본 문서는 그 매핑을 **배치 차원으로 구체화**할 뿐, 소유권을 재정의하지 않는다. 어긋날 경우 [PROMPT-LAYER.md]가 우선한다.

## 1. 작성을 지탱하는 네 가지 원칙

### 원칙 1 — 우선순위 ≠ 배치 순서
레이어 우선순위(`SAFETY > CORE > MEMORY > STORY > CHARACTER > USER`)는 **충돌 시 누가 이기는가**의 규칙이며, **물리적 배치 순서와는 다른 축**이다. 둘을 혼용하지 않는다.

- 우선순위 1위 **SAFETY**는 맨 앞에 놓이지만, 대화가 길어지면 생성 지점에서 멀어져 *묻힌다*. 따라서 PHI로 **맨 끝에도 재주입**해야 효과가 유지된다.
- 우선순위 3위 **MEMORY**는 매 턴 바뀌는 유일한 동적 상태이므로, **Depth**로 내역 끝 가까이에 매 턴 갱신 삽입한다.
- 우선순위 6위 **USER**는 의도적으로 PHI 재주입을 **하지 않는다**. 생성 직전에 사용자 설정을 재강조하면 갓모딩(Godmodding) 경로가 열리기 때문이다.

> 핵심: 우선순위는 "퇴거(eviction) 시 끝까지 보존되는 순서"로 이어지고, 배치 순서는 "프롬프트 안 물리적 좌표"다. 5절(퇴거 정책)에서 우선순위가, 2절(다이어그램)에서 배치 순서가 각각 다뤄진다.

### 원칙 2 — 레이어마다 세 가지 질문에 답한다
1. **언제** 들어가는가 — 항상(상시)인가, 조건 충족 시만(조건부)인가
2. **어디에** 들어가는가 — 시스템 프롬프트 앞쪽 / Depth(내역 중간) / PHI(내역 끝, 응답 직전)
3. **얼마나 자주** — 세션 시작 1회 고정인가, 매 턴 갱신인가, 트리거 시에만인가

### 원칙 3 — PHI와 Depth의 역할 분리
- **PHI(Post-History Instructions)**: **정적 가드레일/필터**를 생성 직전에 재주입. **SAFETY·CORE·STORY·CHARACTER의 핵심 규칙만** 운반한다(전문이 아니라 핵심만). 내부 텍스트 순서는 `CHARACTER → STORY → CORE → SAFETY` (SAFETY가 맨 끝 = 생성에 가장 근접).
- **Depth**: **MEMORY의 동적 상태**를 내역 중간에 매 턴 갱신 삽입. PHI가 정적이라면 **Depth는 동적**이다.
- **USER는 PHI·Depth 어디에도 재주입하지 않는다.**

> PHI와 Depth는 [CONTEXT-ARCHITECTURE.md]가 말하는 "감쇠에 맞서는 설계"의 두 도구다. 둘 다 "생성 지점 가까이"를 노리지만, **PHI=정적 가드레일 / Depth=동적 상태**로 운반 대상이 직교한다.

### 원칙 4 — STORY는 둘로 쪼갠다
[CONTEXT-ARCHITECTURE.md] 4부의 "필요할 때만 등장하는 정보(World Info)" 논리에 따라, STORY는 배치상 두 갈래로 나뉜다.

- **STORY-core**: 장르·전제·핵심 세계 규칙·서사 문체(Narrative Style) → **상시, 시스템 프롬프트 앞쪽**
- **STORY-lore**: 조건부 세계관 지식(World Info) → **트리거 조건 충족 시만** 지정 위치에 삽입

소유권은 둘 다 STORY로 동일하다(SSOT 불변). 쪼개는 것은 **배치 전략**이지 소유권 분할이 아니다.

## 2. 전체 조립 구조 다이어그램

아래는 프롬프트의 **물리적 위치(배치 순서)**를 시각화한 것이다. (우선순위가 아니라 좌표임에 유의 — 원칙 1.)

```text
┌─────────────────────────────────────────────────────────┐
│ [시스템 프롬프트 영역 — 맨 앞: 전체 틀을 설정]            │
│                                                          │
│   SAFETY        ← 최상위 방어선 (앞 + PHI 양쪽 배치)     │
│   CORE          ← 출력 메커니즘·형식 봉투                 │
│   STORY-core    ← 장르·전제·세계 규칙·서사 문체           │
│   CHARACTER     ← 인물의 고정 성향·발화 음색              │
│   USER          ← 플레이어 정적 프로필 (앵커 슬롯)        │
│                                                          │
│   ※ STORY-lore = World Info: 위치 고정 아님,             │
│      트리거 충족 시 조건부로 이 영역/내역에 삽입          │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│ [대화 내역 영역 — 중간: 러닝 트랜스크립트(History)]       │
│                                                          │
│   ... 턴 누적 (기억 + 문체 본보기) ...                   │
│                                                          │
│   ↑ Depth 삽입 위치 (내역 끝에서 N번째)                  │
│      = MEMORY 현재 상태를 매 턴 갱신 삽입                 │
│      (MEMORY 동적 상태 전용 — 정적은 PHI가 담당)         │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│ [PHI 영역 — 맨 끝, 응답 직전: 묻힘에 저항]               │
│   ※ 정적 가드레일/필터만 운반. 독립 레이어 아님.         │
│                                                          │
│   CHARACTER 핵심 필터    ← (맨 앞 = 생성에서 가장 멀다)   │
│   STORY 서사 전개 규칙                                    │
│   CORE 핵심 형식 규칙                                     │
│   SAFETY 핵심 가드레일    ← (맨 끝 = 생성에 가장 근접)    │
│                                                          │
│   ※ USER는 PHI에 재주입하지 않음 (갓모딩 방지)           │
│   ※ MEMORY는 PHI 아닌 Depth가 전담                       │
└─────────────────────────────────────────────────────────┘
                          ↓
                  [모델 응답 생성]
```

**PHI 내부 순서가 `CHARACTER → STORY → CORE → SAFETY`인 이유**: "끝에 가까울수록 모델 영향력이 크다"는 공간 논리(2부)에 따라, 가장 보호해야 할 SAFETY를 **맨 끝(생성 지점에 가장 근접)**에 둔다. 이로써 레이어 우선순위(SAFETY 최상위)가 PHI 블록 내부의 물리적 위치로 **재현**된다.

(STORY는 core/lore로 분리하여 7행. 보호 우선순위는 숫자가 클수록 컨텍스트 한도 초과 시 마지막까지 유지 — 기존 레이어 우선순위 방향과 일치.)

| 레이어 | 조립 위치 | 주입 방식 | 갱신 주기 | PHI 재주입 | Depth 재주입 | 보호 우선순위 |
|---|---|---|---|---|---|---|
| **SAFETY** | 시스템 프롬프트 앞 **+ PHI 맨 끝** | 상시 | 세션 1회 고정(앞) + 매 턴(PHI 핵심) | **필요** — 유해 콘텐츠·탈옥 방어선의 핵심 금지선만 (정책 전문 아님). PHI 내부 **맨 끝**(생성에 가장 근접) | 불필요 (정적 가드레일은 PHI 담당) | **7 (최상)** — 끝까지 보존 |
| **CORE** | 시스템 프롬프트 앞 + PHI | 상시 | 세션 1회 고정 + 매 턴(PHI 핵심) | **필요** — 출력 형식·표기 규약·길이 봉투(envelope)의 핵심 골격만. PHI 내부 **CORE 자리**(SAFETY 바로 앞) | 불필요 | **6** |
| **STORY-core** | 시스템 프롬프트 앞 + PHI | 상시 | 세션 1회 고정 + 매 턴(PHI 서사 전개 규칙) | **필요** — 서사 전개 규칙 + 분량 배분(묘사 대 대사 비중) 핵심만. PHI 내부 **STORY 자리**(CORE 앞) | **불필요** — STORY는 정적이라 PHI만 담당(매 턴 바뀌는 장면·진행 상태는 MEMORY가 Depth로 운반) | **4** |
| **STORY-lore** | 위치 고정 아님 — **World Info 트리거 위치**(앞쪽 또는 내역) | **조건부(트리거)** | **트리거 충족 시에만** | 불필요 — 조건부 지식은 트리거가 운반(상시 가드레일 아님) | 트리거가 삽입 위치를 결정(고정 깊이 아님) | **3** (STORY-core와 동급 소유, 휘발성 높음) |
| **CHARACTER** | 시스템 프롬프트 앞 + PHI | 상시 | 세션 1회 고정 + 매 턴(PHI 핵심 필터) | **필요** — 인물의 고정 성향·발화 음색의 핵심 필터만(상태값 아님). PHI 내부 **맨 앞**(생성에서 가장 멂) | 불필요 (음색은 정적 → PHI 담당) | **2** |
| **USER** | 시스템 프롬프트 앞 — **앵커 슬롯** | 상시 | 세션 1회 고정 | **제외(의도적)** — 생성 직전 재강조 시 갓모딩/가스라이팅 경로가 열림 | **제외** — 동적 재삽입 대상 아님(정적 프로필) | **1 (최하)** — 가장 먼저 압축 대상 |
| **MEMORY** | **Depth(내역 끝 가까이)** | 상시(주입은 매 턴) | **매 턴 갱신** | **제외** — 정적 슬롯(PHI)에 동적 상태를 싣지 않음 | **필요** — **내역 끝에서 N번째**(생성 지점 인접)에 현재 상태 매 턴 삽입 | **5** — 진행 상태/사실은 강하게 보존(요약 압축으로 대응) |

> **표 읽기 보조**
> - **조립 위치**: 시스템 프롬프트 앞 / Depth(내역 중간) / PHI(맨 끝) / 앵커 슬롯
> - **주입 방식**: 상시 / 조건부(트리거) / 혼합(STORY는 core=상시, lore=조건부)
> - **PHI 재주입**: 운반하는 것은 항상 **핵심 규칙만**이며 레이어 전문이 아니다.
> - **Depth 재주입 "N번째"**: MEMORY는 생성에 가장 가깝도록 내역 **끝에서 매우 얕은 깊이**(끝에서 1~2번째 수준)에 둔다. 깊을수록 다시 묻히므로 끝에 붙인다.
> - **보호 우선순위**: 5절 퇴거 정책과 직결된다.

## 4. 레이어별 배치 근거 (테이블 보강)

### ① SAFETY가 "앞 + PHI" 양쪽에 들어가는 이유
SAFETY는 우선순위 1위지만, 맨 앞에만 두면 [CONTEXT-ARCHITECTURE.md] 3부가 경고한 **감쇠**를 그대로 맞는다. 대화가 길어질수록 앞쪽 시스템 프롬프트와 생성 지점 사이에 내역이 쌓이고, 모델은 앞선 지시를 "먼 과거의 일"로 간주한다. 안전 방어선은 묻혀서는 안 되는 지시의 전형이므로, **맨 앞(전체 틀 설정) + PHI 맨 끝(생성 직전 재확인)**의 이중 배치로 영향력을 끝까지 유지한다. PHI 내부에서도 SAFETY를 **맨 끝**에 두어, 안전 규칙이 PHI 블록 안에서조차 최종 영향력을 갖게 한다.

### ② MEMORY가 Depth로 들어가는 이유 (PHI가 아닌 이유 포함)
MEMORY는 6레이어 중 **유일한 동적 상태값(State)**으로, 매 턴 변하고 누적된다(호감도, 챕터 진행, 활성 플래그 등). 반면 **PHI는 정적 슬롯**으로, 세션 내내 거의 고정된 가드레일/필터를 운반하도록 설계됐다. 매 턴 바뀌는 현재 상태를 정적 슬롯에 실으면 역할 직교가 깨진다. 따라서 MEMORY는 **내역 끝 가까이에 매 턴 새로 삽입되는 Depth**가 전담한다. 이 분리로 **PHI=정적 가드레일 / Depth=동적 상태**라는 깨끗한 역할 구분이 완성된다. 또한 Depth는 현재 상태를 생성 지점 바로 앞에 되살려, 모델이 "지금의 관계·진행"을 망각하지 않게 한다.

### ③ USER가 PHI 재주입에서 제외되는 이유
우선순위 체계에서 **CHARACTER > USER**인 핵심 이유는, 사용자의 가스라이팅/갓모딩에 의한 캐릭터 붕괴를 원천 차단하기 위함이다. PHI는 "생성 직전 마지막 정보"로서 모델 영향력이 가장 크다. 만약 사용자 설정/발화를 PHI로 재강조하면, 사용자가 생성 직전에 캐릭터를 덮어쓰는 **갓모딩 경로**가 열린다. 즉 USER를 PHI에서 제외하는 것은 우선순위 원칙(CHARACTER > USER)을 **배치 차원에서 강제**하는 장치다. USER의 정적 프로필은 시스템 프롬프트 앞쪽 앵커 슬롯에 한 번 두는 것으로 충분하며, 진행 중 변한 사용자 상태(승진·칭호 등)는 USER가 아니라 **MEMORY가 Depth로** 운반한다.

### ④ STORY가 core/lore로 쪼개지는 이유
[CONTEXT-ARCHITECTURE.md] 4부는 두 가지를 지적한다. **맥락 공간은 유한하고, 관련성은 맥락적**이라는 것이다. 장르·전제·서사 문체처럼 **모든 턴에 항상 필요한** 거시 설정(STORY-core)과, 특정 장소·인물·사건이 화제에 올라야 의미가 생기는 **조건부 세계관 지식**(STORY-lore = World Info)은 필요 시점이 다르다. 후자를 상시 적재하면 공간을 낭비하고 무관한 배경으로 맥락을 흐린다. 그래서 STORY-core는 **상시·앞쪽**, STORY-lore는 **트리거 충족 시에만** 삽입한다. 둘의 소유권은 모두 STORY로 동일하며(SSOT 불변), 분리는 **배치 전략**일 뿐이다.

## 5. 감쇠 대응 전략 요약 (6레이어 어휘로 재서술)

[CONTEXT-ARCHITECTURE.md] 3부 "흐려짐에 맞서는 설계"를 6레이어 어휘로 다시 정리한다. 감쇠의 근본 원인은 **정적 레이어가 맨 앞에 있어 내역이 쌓일수록 생성 지점에서 멀어지는 것**이다. 각 레이어는 다음 방식으로 저항한다.

| 감쇠 원인 | 대응 메커니즘 | 어느 레이어가 어떻게 저항하나 |
|---|---|---|
| 앞쪽 정적 지시가 묻힘 | **PHI 재주입** | SAFETY·CORE·STORY-core·CHARACTER가 핵심 규칙을 맨 끝에 되살려 영향력 유지 |
| 현재 상태(관계·진행)를 모델이 망각 | **Depth 삽입** | MEMORY가 현재 상태를 내역 끝 가까이 매 턴 되살림 |
| 내역 자체가 잘못된 문체 본보기가 됨 | **내역 교정 / "처음부터 제대로"** | CORE(출력 형식)·STORY(서사 문체)·CHARACTER(발화 음색)의 위반 사례를 내역에서 제거·교정 |
| 무관한 배경이 맥락을 흐림 | **조건부 삽입(World Info)** | STORY-lore가 관련될 때만 등장하여 공간을 아낌 |
| 사용자 흉내·비계 누설로 턴 경계 붕괴 | **Stop Strings(턴 경계)** | CORE가 "AI의 한 턴이 어디서 끝나는가"를 정의 |

> 한눈 요약: **정적 가드레일은 PHI로, 동적 상태는 Depth로** 생성 지점 가까이 되살리는 것이 감쇠 대응의 두 축이다. 나머지는 내역 위생(교정)과 공간 절약(조건부 삽입), 경계 보호(Stop Strings)로 보완한다.

## 6. 퇴거 정책 (컨텍스트 한도 초과 시)

컨텍스트 공간은 유한하므로, 한도에 근접하면 무엇을 먼저 압축·제거하고 무엇을 끝까지 보호할지 정해야 한다. **퇴거 순서는 보호 우선순위(3절 테이블)의 역순**이며, 그 근거는 레이어 우선순위 및 정적/동적 구분에 있다.

### 압축·제거 순서 (먼저 → 나중)

1. **USER 정적 프로필의 부가 항목** (보호 1, 최하)
   - 근거: 우선순위 최하위이며, 진행에 꼭 필요한 사용자 상태는 어차피 MEMORY가 별도로 보관한다. 초기 프로필의 세부 묘사는 캐릭터 무결성에 영향이 적다.
2. **STORY-lore(World Info)의 비활성 항목** (보호 3)
   - 근거: 조건부 지식은 현재 화제와 무관하면 휘발시켜도 안전하다(트리거 시 재삽입 가능). 본질적으로 "필요할 때만" 존재하도록 설계됐다.
3. **CHARACTER 상세 배경의 부가 묘사** (보호 2 → 핵심 필터는 보존, 부연만 압축)
   - 근거: 인물의 핵심 성향·발화 음색 필터는 PHI로 항상 재주입되므로, 앞쪽 전문(full text)의 부연 설명은 압축해도 캐릭터가 붕괴하지 않는다.
4. **History(대화 내역)의 오래된 구간 → MEMORY 요약으로 대체** (보호 5: 사실·상태는 보존)
   - 근거: MEMORY는 History의 파생 요약이다. 오래된 원문 턴을 요약으로 갈음하면 확정 사실·상태는 보존하면서 공간을 회수한다. (단, 최근 턴은 문체 본보기로서 남긴다.)
5. **STORY-core의 부연** (보호 4 → 핵심 규칙·서사 전개 규칙은 보존)
   - 근거: 핵심 세계 규칙과 서사 전개 규칙은 PHI로도 재주입되므로, 앞쪽 거시 설정의 부연은 후순위로 압축 가능하다.

### 끝까지 보호되는 것 (마지막까지 유지)

- **SAFETY 핵심 가드레일** (보호 7, 최상) — 어떤 경우에도 제거 금지. 앞 + PHI 양쪽 배치 자체가 보호 장치다.
- **CORE 핵심 형식·턴 경계** (보호 6) — 출력 구조가 무너지면 "무너진 조립"이 되므로 보호.
- **PHI 슬롯 전체와 Depth 슬롯** — [CONTEXT-ARCHITECTURE.md] 5부의 "보호되는 구조(Pinned)" 원칙에 따라, 이 삽입 슬롯들은 **삭제 불가(켜고 끄기만 허용)**. 슬롯 자체가 사라지면 감쇠 대응 능력 전체가 붕괴한다.

> 퇴거의 일관된 논리: **(1) 우선순위가 낮을수록**, **(2) 다른 곳(PHI·MEMORY 요약)에서 복원·재주입될수록**, **(3) 조건부(휘발 가능)일수록** 먼저 비운다. 반대로 우선순위가 높고, 복원 경로가 없고, 상시 필수인 것은 끝까지 지킨다.

## 7. 수용 기준 점검 (자기 검증)

- 6개 레이어(STORY는 core/lore 포함 **7행**) 전부 3절 테이블에 빠짐없이 채워짐
- **우선순위(충돌 규칙)와 배치 순서(물리적 위치)를 혼용하지 않음** — 원칙 1 및 2절 다이어그램 주석에서 명시 구분
- **PHI 내부 텍스트 순서 `CHARACTER → STORY → CORE → SAFETY` 명시** — 2절 다이어그램 및 직후 설명
- **USER가 PHI 재주입에서 제외된 이유 설명** — 4절 ③
- **MEMORY가 Depth로 들어가는 이유(PHI가 아닌 이유 포함) 설명** — 4절 ②
- **감쇠 대응 전략을 6레이어 어휘로 재서술** — 5절
- **퇴거 정책에 보호 우선순위와 그 근거 포함** — 6절
